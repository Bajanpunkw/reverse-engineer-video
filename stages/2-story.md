# 2. Story and scene table

The story is new, the skeleton is the original's. Whether the story is interesting is the user's call: the agent proposes, the user says yes/no before anything is built.

## Steps

1. **The original's skeleton** — from the frame sheet and the pulse, write it down beat by beat: how it opens (an event in the first second?), how the stakes rise, how often the caption and the scene change, where the climax is, how it ends. That's the formula; keep it.
2. **2–3 topic options** in that skeleton, one line each, with what's visible in the first second. Think about where the video will live (for a social post — a topic close to that audience).
3. After the choice — **the scene table**: video time, what's on screen, caption/line, number, transition, sound event.
4. **Real numbers on screen** — check against primary sources; put a "fact — value — source — date" table into `style.md`. Mark anything made up as an illustration.
5. **Check visual difficulty** of each scene before the OK: anything hard to draw in code (crowds of realistic people, faces, liquids, realistic animals) gets replaced or simplified in the original's style — and say so in the pitch.
6. **Length:** vertical ≤ 60 s. Count the ladder from that: how many milestones fit at the doubling rate, whether a time-lapse is needed at all.

## Pacing rules

- The first second is an event or a question on screen, not an intro.
- Something on screen always changes: the camera drifts, the number runs, the caption changes every ~3–5 s, the scene every 8–12 s (or as the original measures).
- No dead zones: a still frame longer than ~3 s gets reworked.
- The ending is a payoff or a hook shown as a picture, not a cut into silence. For escalations — a black screen with a question: "So what should we … next?".

## The "escalation" skeleton (OutwardAnimates and the many "What if X doubled every N seconds" channels)

An ordinary start → milestones with everyday comparisons every ~4 s (a home, a city, a country…) → "PAST THE MAX" when the real world runs out → (optionally) a TIME-LAPSE tag compressing story time → space → black screen with a question. The number grows by a formula (N(t) = N0 · 2^((t − t0)/step)); milestones are computed from the formula, not picked by hand.

A TIME-LAPSE tag is only needed when the ladder doesn't fit the length. A simpler option: double faster (every 1 s instead of 2 s) and end earlier — the title's promise stays honest the whole way.

🛑 To the user: the ladder / story as a table + what will be hard to draw.

## Lessons

- "A vs B" styles: the "right" half must be the same action as the left with a different outcome (push → the boulder rolls back / push → a stopper holds it). An abstract mechanism (a boulder riding a conveyor belt by itself) wasn't understood. The metaphor must read without explanation.

- Vertical videos ≤ 60 s — there is no point stretching them. With "doubles every 2 s" the trip from 1 to 8 billion alone takes 66 s; doubling every second fits.
